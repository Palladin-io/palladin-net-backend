Jednorazowy canonical cutover przed produkcją

Nie utrzymujemy ścieżki zgodności ani dwóch aktywnych suite. Cały protokół, klienci i fixtures przechodzą atomowo na jeden docelowy kontrakt.

Zdefiniuj docelową suite

Jeden identyfikator obejmuje AEAD, wrapping, signing, KDF, AAD i format kluczy.

Zmień wszystkie komponenty

Backend, web, mobile, Agent runtime oraz wspólne contract vectors wdrażają ten sam format.

Zresetuj dane testowe

Stare envelope, profile i kolejki są usuwane; nie powstaje kod dual-read ani migracja produkcyjna.
